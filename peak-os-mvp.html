MVP 기획본

1단계에서 만들 것과 만들지 않을 것을 정한 문서입니다. 기존 파라곤 데이터를 읽기만 하는 범위까지가 MVP이며, 입력·수정과 돈 관련 기능은 다음 단계로 미룹니다.

GOAL

MVP로 확인하려는 것

새 시스템을 전부 만들어 놓고 "쓸 만한가"를 묻는 방식은 위험합니다. MVP는 가장 위험이 적은 범위로 먼저 만들어 보고 판단하기 위한 단계입니다.

확인하려는 것은 세 가지입니다.

  • 기존 데이터가 새 화면에서 제대로 보이는가 — 파라곤에 쌓인 일정·업무·프로젝트·채팅·보고서를 그대로 불러와 확인합니다.
  • 직급과 소속에 따라 다르게 보이는 구조가 성립하는가 — 대표·팀장·구성원이 각각 다른 범위를 보는지 확인합니다.
  • 흩어진 매출이 자동으로 집계되는가 — 일일보고서에서 영업자별·기간별 매출이 손으로 세지 않고 나오는지 확인합니다.
MVP 한 줄 정의

기존 파라곤 데이터를 건드리지 않고, 새 화면에서 권한에 맞게 보여 주는 것까지.

SCOPE

범위

MVP에서 가장 중요한 결정은 무엇을 넣지 않을지입니다. 아래 오른쪽 항목은 못 만드는 것이 아니라, 이번 단계에서 일부러 뺀 것입니다.

MVP에서 뺀다OUT

  • 정산서·급여·세금계산서

  • 지사별로 완전히 분리된 지면
  • 제안서·교육자료 드라이브 연결
  • 사내 SaaS 목록과 계약 관리
  • 외부 플랫폼 API 정산 연동

왜 쓰기를 뺐는가

새 화면에서 잘못 저장하면 실제 운영 데이터가 망가집니다. 읽기만 하는 동안에는 무엇을 눌러도 되돌릴 일이 생기지 않습니다. 화면 구조가 맞다는 확인이 끝난 뒤에 쓰기를 여는 것이 안전합니다.

왜 돈 관련 기능을 뺐는가

정산·급여·세금은 실제 자료를 아직 받지 못했습니다. 자료 없이 화면부터 만들면 예시 금액을 채워 넣게 되고, 그 숫자를 실적으로 오해할 위험이 생깁니다.

매출 집계 기준

일일보고서의 매출 항목만 더합니다. 리워드·블로그·플레이스 등 34개 상품 항목이 대상이고, 수금액과 미수잔액은 매출이 아니므로 제외합니다. 기간과 단위(일·주·월·분기)를 바꿔 가며 영업자별·상품별로 볼 수 있습니다.

MVP 기간의 숫자는 참고용입니다

집계 화면을 검증하려고 4~7월 데이터를 불러왔지만, 이 기간 보고서는 정확하지 않다고 확인되었습니다. 실적 판단은 8월 데이터부터 하시면 됩니다.

RULES

MVP에서 지킨 원칙

1. 운영 데이터는 읽기만 한다

등록·수정·삭제 요청이 아예 나가지 않도록 만들었습니다. 자동 검사가 실제로 오간 요청을 전부 확인해서, 조회가 아닌 요청이 하나라도 있으면 실패하도록 잠가 두었습니다.

확인용 화면과 실제 운영 시스템은 서버도 데이터베이스도 분리되어 있습니다. 확인 단계에서 무엇을 하든 운영에는 영향이 없습니다.

2. 없는 숫자는 만들지 않는다

자료를 받지 못한 화면에는 예시 금액을 넣지 않고 "아직 전달받은 실제 데이터가 없습니다"로 비워 둡니다. 데이터가 비었을 때 금액 자리에 임의의 숫자가 채워지지 않는지도 검사로 잠가 두었습니다.

3. 쓰던 방식을 바꾸지 않는다

파라곤의 정보 구조를 그대로 유지합니다. 기능 이름은 메뉴 탭에서만 영어를 쓰고 화면 안의 설명은 한글입니다. 직원들이 새로 배울 것이 없어야 합니다.

4. 글자가 작으면 안 된다

가독성을 성능보다 앞에 두었습니다. 넓은 화면에서 내용이 가운데 좁은 폭에 갇히지 않게 하고, 조직도는 화면 크기에 맞춰 자동으로 커지거나 작아집니다.

MVP 성공 기준

아래를 모두 만족하면 MVP는 끝난 것으로 보고 다음 단계로 넘어갑니다. 현재 다섯 개 중 다섯 개를 만족합니다.

01 운영 데이터가 새 화면에서 정확히 보인다 충족

집계 숫자를 운영 DB와 직접 대조해 일치를 확인했습니다.

02 운영 데이터가 한 건도 바뀌지 않는다 충족

데스크톱·모바일 실측에서 조회 외 요청 0건.

03 직급에 따라 보이는 것이 달라진다 충족

일반 구성원 계정에서 최종정산서와 권한 관리가 보이지 않는 것을 검사로 확인.

04 큰 모니터와 휴대폰에서 모두 쓸 수 있다 충족

1680 · 1440 · 390px에서 가로 넘침 0px.

05 없는 데이터를 지어내지 않는다 충족

데이터가 비었을 때 금액이 채워지지 않는지 검사로 잠금.
